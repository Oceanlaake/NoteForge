# AVL Trees, Splay Trees, and Amortized Analysis
> 学习两种优化二分查找树的数据结构，以及三种摊还分析方法
## AVL Trees
**回顾树的两个概念**

- 深度（depth）：针对于某个节点而言，等于其到根节点路径长度，根节点深度为0（相当于父节点深度+1）
- 高度（height）：
    - 某个节点的高度：从某个节点开始到其任意叶子节点的最长路径长度
    - 整棵树的高度：根节点的高度（自然可以得到，空树高度为-1）

> **AVL Tree是满足height balanced条件的BST**

**height balanced**：

我们将整棵树记作$T$，左子树为$T_{L}$，右子树为$T_{R}$，那么，当满足以下两个条件时，树$T$是height balanced的：
- $T_{L}$和$T_{R}$都是height balanced的
- $|height(T_{L}) - height(T_{R})| \leq 1$

**balance factor**：$BF(node)=height(T_{L}) - height(T_{R})$ 

**AVL Tree的插入操作**：

1. 从插入的节点w开始，向上回溯并检查每个节点的BF值
2. 如果到根节点路径上所有节点的BF值均正确，则无需调整
3. 遇到trouble点时，我们则向下伸展两次
    - 如果为$zig-zig$，进行一次旋转
    - 如果为$zig-zag$，先对子节点进行一次旋转，然后再对自己进行一次方向相反的旋转
    - 最后，更新所有节点的BF值

值得注意的是，调整过后以这个节点为根节点的子树高度相较与修改之前是不变的，这说明在这之前的节点完全无需修改了
>自行编写代码时遇到的比较巧妙的点
>
>1. 使用递归的方式，这样我们可以记住操作路径，不用维护每个节点的父节点
>2. 维护每个节点的高度（而不是BF值）

**AVL Tree的删除操作**：

在这种情况下，我们只能依次检查到根节点上的每一个点（有可能要进行大量的调整）

**高度为h的树的最小节点数**：

要使节点数最小，必须是左右子树高度一个为h-1，一个为h-2，可由斐波那契数列得到$n_{h} = F_{h+3}-1$（其中$F_{n}$表示第n个斐波那契数，且$F_{0}=0, F_{1}=1$）
## Splay Trees
在我们访问二叉搜索树的元素时，我们难免遇到一些访问频率特别高的元素，我们可以显式地将他们转换到整棵树的root位置，防止出现访问操作始终为最高复杂度的特殊情况

- 然而如果我们只是将一个节点和它的父节点进行简单旋转的话，想象一个链状的树，每次取最下面的节点，都要经历$O(N)$的时间
- 所以当出现zig-zig的形状时，我们从另外一边开始旋转
## Amortized Analysis



### 势能分析法(potential analysis)
!!! note "怎么去想"
    就像是在你要分析的函数旁边放置一个“水温计”，我们在分析这个函数的复杂度的时候算上这个水温计的变化（函数操作往往会影响水温计的数值），最后可以求出这个函数复杂度的上界,这个水温的往往取大小，内容

    $$
    \hat{c}_i = c_{i-1} + \Phi(D_i) - \Phi(D_{i-1}) \\
    \sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0)
    $$

    ??? question "multiple stack"
        维护一个栈，我们可以对它进行 push 、pop 、multipop（一下子弹出k个元素）

        此时的水温计就是栈内的元素容量：push 的复杂度为2，而两种 pop 的复杂度都与势能的变化量抵消，因此为0
    ??? question "splay tree"
        与上一个例子不同的是，splay tree 是对一个节点分析出它的操作时间复杂度为$O(logN)$
        
        对于一个节点，我们有
        
        $$
        zig: \hat{c}_i \leq 3*(R_i - R_{i-1}) \\
        zig-zig/zig-zag : \hat{c}_i \leq 3*(R_i - R_{i-1})
        $$
